---
title: 冲突处理
description: 当 ProtoDock 和 Agent 同时修改 manifest 时，如何理解提示并选择处理方式。
---

打开本地项目后，ProtoDock 会轻量监测 `protodock.project.json` 是否被其他工具或 Agent 修改。检测只读取项目清单文件，不递归扫描 `pages/**`、`docs/**` 或 `assets/**`。

## 什么时候会检查

ProtoDock 会在窗口重新获得焦点时检查一次 manifest。如果当前画布有未保存改动，它还会额外低频检查，避免 Agent 在后台更新项目清单后你继续基于旧状态编辑。

## 编辑中的外部变更

如果编辑过程中检测到本地清单有更新，ProtoDock 会弹窗提示：

- `读取本地变更`：放弃当前内存状态，重新读取磁盘文件。
- `继续编辑` / `稍后处理`：保留当前界面状态，不重复提示同一次外部变更；后续保存时仍会再次确认冲突。

如果你刚让 Agent 新增页面，通常应该先选择 `读取本地变更`，让 ProtoDock 重新读取 Agent 更新后的 manifest。

## 保存前冲突

保存前如果磁盘上的 `protodock.project.json` 已经被其他工具或 Agent 修改，ProtoDock 也会弹窗提示：

- `读取本地变更`：放弃当前内存状态，重新读取磁盘文件。
- `覆盖本地文件`：用当前 ProtoDock 状态写回磁盘。
- `取消`：不保存，继续保留当前界面状态。

## 推荐处理方式

| 场景 | 建议 |
| --- | --- |
| Agent 刚新增或注册页面 | 读取本地变更 |
| 你刚在画布上排完流程，但 Agent 同时改了 manifest | 先取消，确认双方改动后再保存 |
| 你确定磁盘上的变更不需要保留 | 覆盖本地文件 |
| 不确定变更来自哪里 | 先不要覆盖，检查 `protodock.project.json` 的差异 |

<Warning>
  覆盖本地文件会用 ProtoDock 当前内存状态写回 manifest。只有在确认不需要保留 Agent 的外部修改时再使用。
</Warning>
