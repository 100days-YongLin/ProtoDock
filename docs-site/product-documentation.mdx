---
title: 产品文档规范
description: 用可执行、可验收的方式描述 ProtoDock 页面和业务功能。
---

ProtoDock 的 `docs/<page-id>.md` 是产品、设计、研发和 Agent 对齐页面行为的产品文档，不是源码清单或导出说明。优秀的文档需要回答：为什么有这个页面、谁在什么情况下使用、系统如何反馈、业务规则如何判断，以及什么结果才算做对。

## 描述公式

描述功能时优先使用下面的完整句式：

> 当某类用户处于某个前置条件，为了完成某个目标执行某项操作时，系统应产生可观察的结果；出现异常或边界条件时，系统应给出明确处理并保留后续操作路径。

不要只写“点击按钮跳转页面”。应说明用户身份、触发条件、目标页面、数据变化、成功反馈和失败处理。

## 页面文档结构

每个页面文档应包含：

```md
# 页面名称

> 所属功能：账号绑定

## 页面定位
## 使用场景
## 前置条件
## 页面内容
## 交互规则
## 业务规则
## 状态与异常
## 数据影响
## 产品验收
## 非本期范围
```

页面定位解释用户问题和页面职责；页面内容列出用户真正能看到或操作的模块；交互规则写清入口、操作、反馈、跳转和返回；业务规则承载权限、次数、金额、有效期和优先级；状态与异常覆盖加载、空数据、成功、失败、无权限和重复操作；数据影响明确读取、写入、同步和刷新时机。

源码目录、组件名、`initialScreen` 和 React 实现不应放在 PRD 主体。ProtoDock 已在页面信息二级视图中展示 `sourceDir`、`entry` 和 `doc`。

## 中文验收场景

产品验收统一使用“前提 / 操作 / 预期”，不要求团队理解英文 `Given / When / Then`：

```md
## 产品验收

### 验收场景 1：手机号绑定成功

- 前提：当前手机号存在唯一 APP 账号，且该账号尚未绑定微信用户。
- 操作：用户确认通过当前手机号绑定。
- 预期：系统完成绑定、同步宝宝资料，并进入“我的绘本”。
```

“预期”必须是可以观察和判断的结果，例如页面跳转、状态变化、数据写入、提示文案或可继续执行的操作。不要使用“体验正常”“展示正确”“功能可用”等无法客观验收的表述。

## 文档质量校验

ProtoDock 校验器会检查最终 ZIP 中的产品文档：

- 是否包含标准章节；
- 产品验收是否使用“前提 / 操作 / 预期”；
- 是否残留“请填写”占位内容；
- 是否把源码位置和技术实现放进 PRD 主体。

为兼容旧项目，产品文档问题默认作为警告，不阻止普通上传。交付流水线可使用 `--warnings-as-errors` 把这些警告提升为阻断项：

```bash
./scripts/protodock-validate --warnings-as-errors ./project-protodock-upload.zip
```

Agent 不得臆造缺失的业务规则。登录条件、权限、金额、同步范围或异常处理不明确时，应先向产品负责人确认，再完成文档和页面。

## 查看完整产品文档

项目打开后，点击顶部的“完整产品文档”，ProtoDock 会在新标签页生成项目级阅读视图：

- 按 `canvas.groups` 展示业务模块，没有分组的旧项目按画布页面顺序展示；
- 每个页面同时展示带设备框的原型截图和对应 Markdown 产品文档；
- 封面展示项目变更历史，包含日期时间、版本号和变更内容，并高亮末条当前版本；
- 左侧目录可以快速定位业务模块和页面；
- 点击截图可以查看大图，右上角可以打印或导出 PDF；
- 公开分享页同样提供打印按钮；首次打印会生成并缓存完整原型截图，打印时用截图替换可交互原型，只输出产品文档正文；
- 点击顶部“返回流程图”会优先回到原 Canvas 标签，无法关闭当前标签时则在当前标签打开来源流程图；
- 首次打开会并行生成截图，并在页面之间复用相同图片、字体和样式资源；单张截图失败不影响其他文档阅读。
- 截图完成后会写入浏览器持久缓存。再次打开完整产品文档时直接复用；页面目录、公共素材、设备规格或安全区变化后自动重新生成受影响截图。

这个视图只负责汇总和阅读，不会生成第二份总 PRD，也不会把截图写回项目。`docs/<page-id>.md` 始终是文档来源，因此产品经理在右侧修改并保存页面 PRD 后，再次打开完整产品文档即可看到最新版。
