---
title: 统一发布
description: 一次生成稳定公开预览，并可同步到同名 GitHub 分支。
---

部署内置 Python 服务后，点击右上角 **发布**，可以把同一份 ProtoDock 项目同时发布为公开预览和 GitHub 分支。

```bash
PROTODOCK_PORT=6080 python3 server.py
```

## 发布标识

填写 `产品标识` 和 `版本` 后，ProtoDock 会使用同一标识生成 Git 分支和分享路径。

```text
产品标识：pictale
版本：v1
Git 分支：pictale/v1
公开链接：/s/pictale/v1
最新版入口：/s/pictale/latest
```

再次发布 `pictale/v1` 会更新原有内容，固定版本链接保持不变。每次成功发布还会把 `/s/pictale/latest` 指向该产品最后一次完整发布成功的版本，适合长期发给产品、设计和研发；旧产品没有最新版指针时会按最近发布时间自动兼容。旧版随机 ID 链接 `/s/<share-id>` 继续兼容，但新发布不再要求用户区分“新建分享”和“更新分享”。

发布成功后点击 **复制更新文案**，可以一次复制项目与版本、本次更新内容、当前版本链接、最新版入口和 GitHub 分支链接。本次未同步 GitHub 时不会带出旧的仓库链接。

## 项目包

打开本地项目后，ProtoDock 会自动打包当前目录；没有目录权限时，也可以拖入或选择项目 ZIP。ZIP 根目录必须直接包含 `protodock.project.json`、`pages/`、`docs/` 和可选的 `assets/`，不能再套项目名、版本号或交付目录。

ProtoDock 上传包应与完整交付包分开生成。建议使用 `<project>-<version>-protodock-upload.zip` 与 `<project>-<version>-full-release.zip` 区分两类产物，完整交付包不要用于 ProtoDock 发布。

服务端会在写入前一次性检查 manifest 中全部 `entry`、`doc`、Canvas、跨页导航、返回桥接和变更历史。缺失文件、错误的归档根目录、重复节点、悬空连线、节点重叠或无效页面目标会显示具体问题并停止发布。

## GitHub 同步

服务端配置固定 GitHub 仓库后，发布弹窗中的 **同步到 GitHub** 默认开启，也可以按次关闭。Commit message 仅在同步开启时必填。

公开版本和 GitHub 推送使用同一份已校验项目包，并写入同一个 `产品标识/版本`。如果 GitHub 推送失败，服务端会恢复发布前的公开版本，避免分享链接与仓库分支内容不一致。

GitHub 凭据位于折叠的 **GitHub 连接配置** 中。Deploy Key 私钥、GitHub App 私钥和工作目录只保存在服务端，不会进入项目包或公开预览。

## 预览与下载

`/s/<product>/<version>` 默认进入产品文档式预览页：左侧目录按业务分组快速定位页面，中间并排展示真实 iframe 原型与完整 PRD。原型中的按钮、Tab 和返回操作会联动定位到目标页面章节。

需要查看画布节点、连线和右侧文档时，打开 `/s/<product>/<version>/canvas`；长期入口可使用 `/s/<product>/latest/canvas`。这些入口都是只读画布，不允许浏览者编辑 Canvas、文档或页面信息。

公开预览顶部提供项目包下载和 A4 PDF 下载。项目包接口为 `/api/shares/<product>/<version>/download`；PDF 接口为 `/api/shares/<product>/<version>/pdf`，生成状态在 `/pdf/status` 查询。发布成功后服务端会后台预生成 PDF，并按项目内容哈希复用缓存；生成失败时页面自动退回浏览器打印。

## 高速上传

预览域名上传较慢时，可以给浏览器配置单独的直连上传 origin：

```bash
export PROTODOCK_UPLOAD_ORIGIN=http://100.113.173.18:6080
```

浏览器仍使用当前域名生成公开链接，但项目包优先上传到高速 origin 的 `/api/publish`；连接失败时自动回退当前域名。环境变量只填写 origin，不要附带接口路径。
