---
title: 画布协作
description: ProtoDock 如何维护页面节点、连线和右侧 Markdown。
---

ProtoDock 是展示和编排工具，不是页面源码生成器。页面源码可以由设计 Agent 生成；画布布局、节点位置、连线和文本说明是用户在 ProtoDock 中沉淀下来的工作成果。

## 节点

每个节点绑定一个 `pageId`，并从 `pages.<pageId>.entry` 读取页面入口。iframe 会按项目设备规格渲染，再缩放成画布预览。

## 连线

拖拽节点锚点可以创建流程连线。`fromSide` 和 `toSide` 会记录连接方向，导出脚本或 Agent 不应重算这些字段。

## 画布缩略图

画布右下角的缩略图显示全部页面节点、页面组、流程连线和文本备注。蓝色边框表示当前视口在完整画布中的位置。

- 点击缩略图中的位置：将该位置移动到画布中心
- 在缩略图中拖动：连续浏览其他画布区域
- 点击右上角适配图标：将全部画布内容放进当前视口
- 使用右下角缩放按钮：在 `10%-300%` 范围内调整画布

左侧页面列表被搜索或收起时，缩略图和主画布仍然保留完整结构，不会修改 manifest 中的节点坐标和连线。

## 交互预览

顶部“播放原型”打开的右侧设备预览会直接运行页面 iframe，不是页面截图。页面入口中已有的点击、输入、滚动、弹窗和本地状态逻辑会原样执行。

跨 manifest 页面跳转建议在控件上显式声明目标：

```html
<button data-protodock-page="reader-character">查看角色</button>
<a href="protodock:parent-center">家长中心</a>
```

页面脚本也可以调用 `window.ProtoDockPreview?.navigate(pageId)`，或向父窗口发送 `{ type: 'protodock:navigate', pageId }`。为了兼容旧的 HTML-only 原型，当当前页面的唯一出边标签与按钮文案明确一致时，播放器会自动切换到目标页面；不会进行模糊匹配或按控件顺序猜测。

<Warning>
  可部署静态文件不等于静态 DOM。React/Vue/Svelte 导出必须包含构建后的 JavaScript；只输出 `renderToStaticMarkup`、`outerHTML` 或截图会让控件失去事件处理。
</Warning>

## 文档

选中页面节点后，右侧面板会显示页面 Markdown。文档可以绑定到 `docs/<page-id>.md`，保存时写回项目目录。

<Note>
  原型页面是可生成资产，画布排布是用户劳动成果。更新页面前先保护画布。
</Note>

## 页面与节点

每个 manifest page 必须且只能对应一个 canvas node。页面数必须等于唯一 `pageId` 节点数，不能出现缺失节点、重复节点、引用不存在页面的节点或悬空连线。

页面能预览只说明文件完整，并不代表画布已经正确编排。上传检查会同时验证文件与画布。

## 业务分区

画布按一级业务模块划分区域。模块入口、状态页、详情页和操作结果应放在同一局部区域，推荐按“模块入口 → 页面状态 → 操作结果/详情”组织。

新增页面不能统一堆到画布底部，也不能使用随机坐标。底部 Tab、侧边栏等全局导航不绘制跨模块连线；画布只保留关键任务流程，次要入口写进页面文档。

## 页面组

页面组（Canvas Group / Flow Group）用来表达一个完整业务模块，例如“生活记录详情”。组内仍然保留入口页、详情页、弹窗、成功状态和异常状态组成的小型树结构。

在左侧“原型页面”标题旁点击新建组，选择组内页面并指定主入口。新组默认只在左侧列表中收起；创建后可以：

- 收起列表分组：左侧隐藏成员页面，不改变 Canvas
- 搜索页面：按页面名、`pageId`、入口路径或组名过滤左侧列表，不改变 Canvas
- 点击左侧页面：快速定位对应 Canvas 节点，不改变原有树结构和业务连线
- 编辑或删除组：删除组不会删除页面和连线
- 预览组内布局：先查看局部树形排列，确认后只写入当前组节点坐标

无论左侧列表分组是否收起，Canvas 都会展开到页面级，持续显示全部节点、组边界、备注和原始连线。列表状态不会改写 manifest 中的节点坐标或 edge。

`canvas.groups` 是可选字段。旧版 manifest 没有 groups 时，页面列表和画布保持原有行为，不需要迁移。

```json
{
  "id": "group-life-record",
  "title": "生活记录详情",
  "rootNodeId": "node-life-daily",
  "nodeIds": ["node-life-daily", "node-meal-detail", "node-nap-detail"],
  "collapsed": false
}
```

一个节点最多属于一个组，主入口必须是组内成员。上传会阻止重复组 ID、跨组重复成员、缺失主入口和引用不存在节点的组。

## 旧项目分组迁移

旧项目可以直接打开，不强制升级。需要页面组时，建议让 Agent 使用 `protodock-canvas` Skill 完成一次增量迁移：先检查页面、节点、连线和文件完整性，再根据页面文档与关键流程输出分组提案，确认后只写入 `canvas.groups`。

迁移不能同时重排画布，也不能改写页面注册、节点坐标、原有连线、备注或未知字段。无法确定业务归属的页面保留在“未分组”；需要调整组内树形布局时，再单独使用“预览组内布局”并确认应用。完整提示词见 [Skill 安装与文件契约](/ai-agent-skills#用-skill-升级旧版原型)。

## 布局与连线

- 同层节点保持统一方向和间距，推荐横向 `480-600px`、纵向 `600-700px`
- 节点不能重叠，状态页应靠近所属入口；坐标允许为负数
- 上下流程优先使用 `bottom → top`，同层流程优先使用 `right → left`
- 非共享端点的连线交叉应为 0，连线不能穿过无关节点或页面预览区域
- 单个节点连线过多时，应拆成局部流程或去掉非核心路径

## 上传校验

ProtoDock 解压最终 ZIP 后会检查：

- `pageCount === uniqueNodeCount`
- 缺失、重复或未知页面节点为 0
- 悬空连线和重复连线为 0
- 节点重叠为 0
- 每条边的 `from/to` 节点存在
- 所有页面 `entry` 和 `doc` 文件存在
- 页面组 ID 唯一，组成员和主入口均引用现有节点
- 同一节点不能同时属于多个组

上述完整性错误会阻止上传。连线交叉、连线穿过无关节点和间距不足会在上传成功后给出明确警告，不会触发自动重排。

## 重排保护

普通 build/export 不得修改 `canvas.nodes`、`canvas.edges` 或 `canvas.notes`。只有用户明确要求重排，或显式使用 `--relayout` / `--reset-canvas` 时才允许更新画布。

重排前必须备份 manifest；自动布局只能修改 `canvas`，不能重写 `pages`、`project.id` 或未知字段。布局工具应先生成预览，得到确认后再写入，上传过程不会偷偷重排。
