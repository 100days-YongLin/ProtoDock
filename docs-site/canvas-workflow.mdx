---
title: 画布协作
description: ProtoDock 如何维护页面节点、连线和右侧 Markdown。
---

ProtoDock 是展示和编排工具，不是页面源码生成器。页面源码可以由设计 Agent 生成；画布布局、节点位置、连线和文本说明是用户在 ProtoDock 中沉淀下来的工作成果。

## 节点

每个节点绑定一个 `pageId`，并从 `pages.<pageId>.entry` 读取页面入口。iframe 会按项目设备规格渲染，再缩放成画布预览。

## 连线

拖拽节点锚点可以创建流程连线。`fromSide` 和 `toSide` 会记录连接方向，导出脚本或 Agent 不应重算这些字段。

## 文档

选中页面节点后，右侧面板会显示页面 Markdown。文档可以绑定到 `docs/<page-id>.md`，保存时写回项目目录。

<Note>
  原型页面是可生成资产，画布排布是用户劳动成果。更新页面前先保护画布。
</Note>

## 页面与节点

每个 manifest page 必须且只能对应一个 canvas node。页面数必须等于唯一 `pageId` 节点数，不能出现缺失节点、重复节点、引用不存在页面的节点或悬空连线。

页面能预览只说明文件完整，并不代表画布已经正确编排。上传检查会同时验证文件与画布。

## 业务分区

画布按一级业务模块划分区域。模块入口、状态页、详情页和操作结果应放在同一局部区域，推荐按“模块入口 → 页面状态 → 操作结果/详情”组织。

新增页面不能统一堆到画布底部，也不能使用随机坐标。底部 Tab、侧边栏等全局导航不绘制跨模块连线；画布只保留关键任务流程，次要入口写进页面文档。

## 布局与连线

- 同层节点保持统一方向和间距，推荐横向 `480-600px`、纵向 `600-700px`
- 节点不能重叠，状态页应靠近所属入口；坐标允许为负数
- 上下流程优先使用 `bottom → top`，同层流程优先使用 `right → left`
- 非共享端点的连线交叉应为 0，连线不能穿过无关节点或页面预览区域
- 单个节点连线过多时，应拆成局部流程或去掉非核心路径

## 上传校验

ProtoDock 解压最终 ZIP 后会检查：

- `pageCount === uniqueNodeCount`
- 缺失、重复或未知页面节点为 0
- 悬空连线和重复连线为 0
- 节点重叠为 0
- 每条边的 `from/to` 节点存在
- 所有页面 `entry` 和 `doc` 文件存在

上述完整性错误会阻止上传。连线交叉、连线穿过无关节点和间距不足会在上传成功后给出明确警告，不会触发自动重排。

## 重排保护

普通 build/export 不得修改 `canvas.nodes`、`canvas.edges` 或 `canvas.notes`。只有用户明确要求重排，或显式使用 `--relayout` / `--reset-canvas` 时才允许更新画布。

重排前必须备份 manifest；自动布局只能修改 `canvas`，不能重写 `pages`、`project.id` 或未知字段。布局工具应先生成预览，得到确认后再写入，上传过程不会偷偷重排。
